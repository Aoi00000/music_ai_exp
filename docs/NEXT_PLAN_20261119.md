## 2. データを増やす目的と方法

### 実測から優先順位を更新

16開発条件のMu＋6sで、ギターTP463／FN101／FP122、ベースTP249／FN47／FP72。余分なギター122音のうち58音は同じ楽器の正解と開始50ms以内で1オクターブ違った。これは倍音誤認等に整合する診断で、原因の証明ではない。正しく対応した704音の終了絶対誤差中央値は約16msだったため、終了を一律に動かすより、余分なオクターブ音と欠落音を優先する。`docs/measurements/error_taxonomy_20261119.json`に保存。

そこで、同じギターで開始80ms以内・±12半音の候補がある音だけを対象とし、元の音高・開始・終了とベースを保護して真偽を学習する2条件を追加した。350音響特徴と、近傍オクターブ音との差を足した704特徴を同じ500更新で比較する。正しいオクターブ重奏をルールだけで消さず、正解ラベルから学習する。これは繰り返し使う開発検証であり、新規テストではない。

Muのネイティブ楽器指定cfg1/2も比較したが、バンド16条件の音符F1は0.8184→0.7925／0.7345へ低下。一律採用はしない。ジャズ教材の小規模補完は改善例だが、ジャズ固有の弱点と断定せず、ジャンル名より実測した誤りを教材選定の基準にする。

今回は、取得済みのGOATの音色違い、GuitarSet、Slakh、FiloBass、人工バンド混合を優先する。元の演奏単位でtrain／validationを分け、同じ演奏の加工違いを別の分割へ流さない。

音色増強では、波形の長さと音程・時刻を変えないゼロ位相EQを用い、正解付きギター単独音だけにメモリレスな歪みも加える。振幅を戻して音量だけの違いと混同しない。複数楽器のミックス全体へ追加の歪みはかけない。リバーブは音の終わりと教師の対応を曖昧にするため、今回の比較には入れない。合成音色は、新しい奏者・弾き方・独立した曲を増やしたものとは数えない。

新しい候補としてEGDB／EGDB-PGも調査した。EGDB-PGの研究は、アンプ等の音色差に対するデータ多様化・音色情報の利用を検証している。[論文](https://arxiv.org/abs/2504.07406)。公開例には27.3GBの部分集合、最新のFLAC版には135.4GBの束があり、全量を無条件に追加する方針にはしない。[部分集合](https://zenodo.org/records/19542613)、[FLAC配布](https://zenodo.org/records/19789500)。利用条件・必要な音色範囲・既存曲との重複・取得量を確認してから、既存データで埋まらない失敗に対応する部分だけを検討する。今回の学習へ導入したとは記録しない。

## 3. 学習と評価の流れ

1. 仮説、変更点、比較対象、乱数、学習量、採否基準をファイルへ固定する。
2. 学習データだけで標準化と重みの学習を行う。検証ラベルをモデル入力へ入れない。
3. 検証で比較し、音符開始・持続音・全音一致・終了・楽器別のどれが改善／悪化したかを調べる。
4. 改善候補だけを選び、重みと閾値を固定してから別データを開く。
5. 同じ評価で何度も試した結果は開発結果として扱う。GOATの以前開封した7演奏を再び未使用とは呼ばない。残るSlakh11元曲は、設定固定後の評価用として保留する。

追加音符モデルは、既存Muの全音を残すため、単純な「削除して見かけをよくする補正」にはならない。ただし候補の誤検出で精度が下がり得る。既存モデル、全候補追加、学習した選別の3つを並べる。選別しても基準に届かなければ、既存モデルを使う。

## 6. コード譜は別の出力・別の評価として完成させる

現行コード解析はCQT＋CNN/双方向LSTM＋構造化デコーダ。BTCは未採用。原ミックスからコード、分離G/Bから音符を求め、双方を保持する。`chordchart.export`で時刻付きコード譜HTML/CSVを出力し、既存画面にも保存ボタンを追加した。小節表示は確認済みBPMと最初の小節頭がある場合だけ行う。

公開5モデルの推論経路では、追加したpower用出力行を使っていなかった。そこでGuitarSetのperformedコードで18録音を診断し、別の60録音を使って出力層全体／新power行のみ／新power行のみ＋正例重み3の3条件を学習した。正式比較では音声の変換も同一にした。選択候補は構造全体の時間一致0.2216→0.2354だが、power部分の認識はまだ低い。表現の追加と高精度な認識を混同せず、標準は自動変更しない。

次は、第三音が実際にある／ない区間を区別する教材と、表現できない省略コードを優先する。音符ラベルから和音を作る場合は、人の和声解釈ラベルと区別し、根音が曖昧な例を勝手に正解としない。コードのroot・triad・7th・分数コード・時間境界を音符F1と別に報告する。テンションを含む実音を消してコード名に合わせる補正は行わない。
