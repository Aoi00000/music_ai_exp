# 次の改善サイクル：誤検出の除去と持続音の保護

11/19の新しい依頼を受けた計画。既存のB受け渡しZIP・既定モデルは固定し、追加実験を別の名前で保存する。目標は強い既存Muと同じ入力・同じ採点で上回ること。検証を繰り返した集合の改善を、未知曲への証明とは呼ばない。

## 1. 今回の仮説

従来のオクターブ補正は対象が狭く、14既知条件では変更がなかった。一方、開始時刻を動かす補正は音符F1を壊した。そこで音高・楽器・開始・終了を一切動かさず、既存Muの余分な音符だけを選別する。ギターだけでなくベースも候補にする。

候補を「開始が正解か」だけで学ぶと、開始の許容差から外れた有用な持続音まで消す可能性がある。比較する教材の答えは次の2通り。

- 開始教師：同じ楽器・音高、50ms以内の一対一対応で残す音を教える。
- 持続保護教師：上の正解音に加え、その音を消すとFrame F1が下がる候補も保護する。教師計算だけに正解を用い、推論の入力には正解を渡さない。

同じ線形モデルで教師の違いを比較し、さらに小型NNで非線形な音響特徴を学ぶ。各3 seed、800更新を事前固定する。Mu本体・分離器は固定したままである。

## 2. 選択と評価の順序

既存の訓練47ギター演奏から、ハッシュで10演奏を内部の設定選択用に分ける。clean/noisy・同じ演奏の音色違いは同じ側へ置く。元々の16開発条件はこの選択には使わない。内部確認のベース奏者は学習側と重複し得るため、全楽器の未知奏者評価とはしない。

37演奏と既存の加工ベースで学習し、内部20条件で方式・閾値を固定する。標準化は学習側だけ。各条件は同じ学習データ・更新量・3 seedを使用する。内部で音符・Frame・終了・全音一致を保護できる候補だけを残す。

固定後に、従来16開発条件と14既知回帰条件で比較する。原音・基準Mu・以前のオクターブ補正＋補完も並べる。悪化する指標と変更音数を隠さない。未開封Slakh11元曲は引き続き11/22の最終設定固定後に留保する。

## 3. 結果に応じた次の一周

1. 学習が効かない場合：内部の偽陽性・偽陰性・音色・同時音数を分類し、追加層の複雑化より教師と教材の不足を確認する。
2. 音色・分離後の教材不足がある場合：取得済みGOATの未使用アンプ／抜粋、音量比を変えた混合、GuitarSetやSlakhの正解を保った加工を追加する。元演奏を分割間に流さず、同じ対照と比較する。
3. 別モデルの候補に必要な音がない場合：候補選別の追加学習で解けないため、採譜器LoRAやMu本体の追加学習の実装・教師トークンを点検する。
4. 新しいデータセットは、残る誤りを埋められ、音源・正解の同期と利用条件を確認できたものを優先する。量を増やすこと自体を成果としない。
