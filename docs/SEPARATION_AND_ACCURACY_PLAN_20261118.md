# 分離と採譜精度の改善計画（2026-11-18）

## 現在の実装と実験の区別

- アプリの標準経路：ファイル変換 → 原音全体をMuScriptor mediumへ入力 → MIDIの楽器情報からギター／ベースを抽出 → 譜面化。`app.py` にDemucsの呼出しはない。
- 分離の試験経路：学習済みHTDemucs-6s → 推定ギター／ベース音声 → 自作A8採譜器。`scripts/a_separation_diagnostic.py` で実行済み。
- 自作EventRefiner：原音のCQTとMuScriptor候補から、対象外／ギター／ベースを提案する。分離は行わない。アプリ標準経路にもまだ接続しておらず、自動適用は無効。

従来の合成バンド音源3区間で、ギター＋ベースの音高集合Frame F1は原音→MuScriptorが0.3848、分離→A8が0.3286だった。これは分離器だけでなく採譜器も変えた比較なので、分離の有効性・無効性は結論できない。自然なバンド録音全般の評価でもない。

追加学習の人工ギター＋ベース混合7区間では、楽器込みFrame F1は0.4310→0.4922、楽器を区別しない音高集合Frame F1は0.6587→0.6565。楽器の振り分けは改善したが、鳴っている全音の認識改善は確認できていない。ギター単独の新評価では小さな低下もある。詳細は `DURATION_REFINEMENT_20261118.md`。

## 1．分離だけを変える比較を最初に行う

MuScriptorの重み、バージョン、推論設定、音声区間、正解、採点条件を固定する。

|条件|採譜器への入力|目的|
|---|---|---|
|M0|原音全体|比較基準|
|M1|HTDemucs-6sの出力からドラム・ボーカル以外を合算|不要パート除去の効果|
|M2|HTDemucs-6sの推定ギターと推定ベースを個別入力|対象楽器ごとの分離の効果|
|Oracle|データセットが持つ正解ギター／ベース音声を個別入力|分離誤差と採譜誤差を切り分ける診断|

M1ではピアノやotherも残る。ギター＋ベースだけにした条件とは区別する。M2では出力MIDIの楽器ラベルを使う方法を基準とし、入力ステムの楽器名で振り直す方法は別条件として記録する。漏れ込んだ別楽器を無条件でギター／ベース扱いする危険を確認する。Oracleは実運用の成績として扱わない。

分離器と再サンプリングの設定を固定し、原音との時間位置・長さ・チャンネルを検査する。分離の聞きやすさだけで採用せず、最終的な音符認識で判断する。ビート検出には原音またはドラムを残して利用し、採譜向けの除去と分ける。

## 2．評価用データを先に固定する

1. 現在の学習／検証データでM0〜M2とOracleを比較し、欠落音、余計な音、オクターブ誤り、開始／終了誤り、楽器誤りを集計する。
2. 最終評価を追加する場合は、まだ採用判断に使っていないSlakhの元曲群を確保し、学習・検証・評価の分割を先に保存する。既に観察したP3、FiloBass、IDMT、従来の3区間を「未使用の最終テスト」と呼び直さない。
3. 同一曲のステム、別区間、エフェクト違いはすべて同じ分割に置く。特徴量の正規化も訓練側だけで決める。
4. ギター＋ベースのみ、ドラム追加、他の有音程楽器追加を比較する。追加ステムは同じ分割内から選ぶ。別曲を重ねた音源は制御用人工ミックスと明記する。
5. ボーカル除去の定量評価には、ボーカルを含む混合音と対象ギター／ベースの正解音符が必要。現在のFiloBass＋GuitarSet人工ミックスではボーカル／ドラム除去の有効性を測れない。

Slakhは音声＋MIDIがあり、この診断と学習に適しているが、合成音源である。未取得曲を増やす際は配布アーカイブの転送量と空き容量を確認する。音声ステムだけのデータを追加しても、それだけで音符の正解ラベルが増えるわけではない。

## 3．診断に合わせて独自学習を変える

### 優先A：候補の採否・楽器判定を、原音と分離音の両方から学習

MuScriptorは固定したまま、原音・推定ギター・推定ベースにおける候補音のCQT、倍音、立ち上がり、持続の特徴を補正器へ渡す。「分離後にも対象音の証拠があるか」「ベースではなくギターに由来するか」を学習する。正解音符は既存データセットから作る。

訓練にも実際の分離器出力を使い、分離漏れや欠けを含む入力と正解を対応させる。正解ステムだけで訓練して、本番では推定ステムに変える条件を混同しない。既存の原音のみ補正器を比較対象として残す。

### 優先B：取りこぼした音を追加できるようにする

現在の補正器はMuScriptorが出さなかった音を作れない。M0とM2の候補を時間・音高で対応付け、分離側だけにある候補を追加候補にする。必要なら既存A8の音高活動・オンセット出力も証拠に使う。

候補を単純に全結合すると誤検出も増えるので、追加候補を採るかを既存の正解音符に対して学習する。候補の重複とギター／ベースの同音重なりを区別し、異なる楽器で同時に鳴る同音は保持する。音源全体の出力終了後に発生する余計な音も誤りとして数える。

### 優先C：開始・終了を修正する

取りこぼしより音長の誤りが支配的ならBより先に着手する。既存A8のframe／onset／offset出力を候補周辺の境界修正に使い、必要なら訓練側の推定分離音で追加学習する。基礎モデルとの競争ではなく、基礎モデルの候補を音響証拠で補う用途にする。

フレームは「今鳴っているか」、オンセットは「弾き始めたか」、オフセットは「終わったか」の教師。損失低下だけで採用せず、検証側のNote F1、Offset F1、Frame F1で確かめる。拍に揃える処理は、その後の譜面整形として評価する。連続ピッチや奏法の推定は別タスクとし、今回確実にできたと宣言しない。

## 4．採用条件と発表で示す価値

- Note F1：音高と発音開始の正しさ。
- Offset F1：上記に音の終わりも加えた正しさ。
- 楽器込みFrame F1：ある時刻の「楽器とオクターブ付き音高」の正しさ。
- 音高集合Frame F1：ギター＋ベース全体として鳴るオクターブ付き音高の正しさ。
- 余計な音／欠落音の数、単音／同時発音別、楽器別、曲別の結果と処理時間。

検証側で採用条件・閾値を決めてから最終評価する。特定条件だけの改善なら、その範囲を明記し、自動適用を一般化しない。少数曲で統計的な優位性や最高精度を主張しない。学習済みモデル単体、分離追加、補正学習追加を段階的に比較し、今回の学習が寄与した部分を示す。

TABへの運指割当で認識音を消し、音響認識が改善したように扱わない。原音、未補正MIDI、補正案、量子化後、TABを別に保存する。弦・フレットの実行可能性と編集時間は、音符認識の精度と別に評価する。
