# 音源分離・上乗せ学習の実測結果（2026-11-18）

**分離による大きな改善が確認できた条件はありますが、すべてのバンド音源で正確になる状態ではありません。** ギター＋ベースの人工ミックスでは分離が有効でした。一方、他楽器を含む合成バンド音源では、拾う音高が増えても楽器判定や発音開始が悪化しました。学習した経路選択も検証の改善を評価全体では維持できず、自動適用は無効のままです。

## 今回実行した比較

MuScriptor medium 0.4.0、同一の公開重み、greedy推論、テンポ推定なしを固定しました。すべての経路をモノラル16kHz・float WAVへ変換し、ピーク正規化は行いません。

|記号|処理|
|---|---|
|M0|原音 → MuScriptor|
|M1|HTDemucs-6sで分離し、ドラム・ボーカル以外を合算 → MuScriptor|
|M2 labels|推定ギター／ベースを個別にMuScriptorへ入力し、出力MIDIの楽器情報を使用|
|M2 forced|上記の各ステムから得た非ドラム音符を、入力ステムの楽器に割り当て|
|M3|原音とM2の候補を単純に結合。音高・開始・持続の重なりで重複を対応付け|
|EventFusion|原音・分離音の証拠を用い、候補の追加／除外を独自学習|
|Router|どの処理経路が有効かを独自学習|
|Oracle|データセットの正解ギター／ベース音声 → MuScriptor。診断専用|

M1には鍵盤やotherが残ります。M2 forcedでは漏れ込んだ他楽器も対象楽器になる可能性があります。Oracleは実際のアプリが取得できる入力ではありません。

## 自分たちで学習したもの

MuScriptorとHTDemucs本体の重みは更新していません。Azure上で次の2種類を教師あり学習しました。

### 1．EventFusion：音符候補を追加・除外するニューラルネットワーク

- 訓練64区間・15,346候補。検証21区間。元曲群・FiloBass奏者の分割を継承し、同一曲の音源違いを別分割にしません。
- 原音・推定ギター・推定ベースのCQT由来82特徴を各々使い、対象楽器、元の候補の有無、候補の由来、音声末尾との関係を加えた254次元が入力です。
- `254 → 64 → 1` のMLP、ReLU、dropout 0.1、16,385パラメータ。ギター／ベースの候補を別々に判定し、両者が同音を鳴らす場合も保持できます。
- 教師は既存の正解音符から作る「持続の重なり80%＋発音開始の対応20%」。新しい演奏音源や手作業の音符ラベルは作っていません。
- AdamW、学習率0.001、重み減衰0.001、seed17、150回の全件バッチ更新。録音ごと、単独／混合の領域ごとの重みを調整します。
- 検証で25／50／100／150更新と追加・除外閾値を比較し、50更新、追加0.75、除外0.25を選択。学習損失の最小値だけで選んでいません。
- 従来の補正器と異なり、分離音だけに現れた音も追加できます。ただし、元音符の開始・終了の直接修正、連続ピッチ、奏法の推定は行いません。

評価ではギター直接入力の音高集合F1が0.5775→0.5781、アンプ録音が0.5986→0.6001という小さな改善でした。人工ミックスは0.6587→0.6589、合成バンドは0.3839→0.3838です。**候補追加が可能になったことと、認識精度が大幅に改善したことは区別します。**

### 2．Router：有効な処理経路を選ぶ決定木

原音と分離音のRMS比・相関、原音からの音符密度・平均音高など12特徴から、各経路の改善量を回帰します。教師は訓練用音源で測ったM0との差です。

最初の「3指標の平均改善量」を学ぶ条件は検証で採用できませんでした。その後、Note／楽器込みFrame／音高集合Frameの**最小改善量**を学び、訓練データセットの重みを均等にした条件を追加しました。これにより、一つの指標の改善で別の悪化を覆い隠しにくくします。両条件とも評価結果を見る前に固定しました。

深さ1／2／3、葉あたりの最小サンプル数4／8、改善量の閾値0／0.02／0.05／0.1を検証で比較しました。採用候補は7ノードの木、最大深さ3、葉あたりの最小サンプル数8、閾値0.02です。全体の基準は、データセット別Note／Frame／音高集合をM0から悪化させず、データセット均等平均のNote＋音高集合を最大化することです。

検証の音高集合F1は0.6589→0.7044でしたが、評価では下表の通りでした。

|対象|M0 音高集合F1|Router 音高集合F1|M0 Note F1|Router Note F1|
|---|---:|---:|---:|---:|
|人工ギター＋ベース混合|0.6587|0.6931|0.4985|0.5662|
|合成バンド|0.3839|0.4133|0.4297|0.1971|
|ギター直接入力|0.5775|0.6535|0.6077|0.6277|
|アンプ録音|0.5986|0.6068|0.6647|0.5985|

音高集合が改善しても、楽器や発音開始が悪化する場合があります。検証の改善が評価全体へ一般化しなかったため、自動切替は本番採用しません。モデルの予測改善量も正答確率ではありません。

## データと評価上の限界

- 既存のBabySlakh、GuitarSet、FiloBassを再利用。Guitar-TECHS P3の未使用マイク録音は、取得済みZIPから追加抽出しました。
- 訓練64区間＝混合48＋単独16。検証21区間＝混合10＋単独11。評価37条件。
- 評価のギター直接入力10件とアンプ10件は同じP3の演奏です。FiloBass単独7件と人工ミックス7件も同じベース演奏です。37件の独立した新曲ではありません。
- 従来のP3・FiloBass・BabySlakhの評価セットは再評価です。アンプ音声は未使用の音響条件ですが、新しい曲や奏者ではありません。公開モデルの事前学習との非重複も保証できません。
- アンプ音声も、予測前に従来と同じ固定の同期検査を通しました。未補正の注釈による値も `raw_annotation_metrics` に保存しています。全注釈を人手で検証した意味ではありません。
- 切出し区間には両端0.25秒の固定ガード、全体録音には全出力を含めた評価を使います。ファイル終了後の余計な推定音も、全体録音では誤りとして数えます。
- 前回とは入力形式・一部のガード条件が異なるので、過去の表との差を学習効果にしません。今回の同条件のM0との差で比較します。
- 4評価音源で再サンプリング後の長さが1サンプルだけ異なりました。経路選択の相関計算だけ最大2サンプルの丸め差を許容し、音声・MIDI・学習済みの木は変更していません。大きなずれはエラーにします。
- しきい値の再選択や学習に評価結果を使っていません。少数曲で統計的優位性や最高精度を主張しません。

## ファイルと担当Bへの引き継ぎ

アプリ `app.py` の標準経路は引き続きM0です。今回の分離・学習機能は実験スクリプトと再利用可能なAPIとして追加し、Bの表示・編集・TAB処理は変更していません。

- `band2tab/separation.py`：学習済み分離器と入力音声の統一。
- `band2tab/fusion.py`：分離由来の新音符を含む候補生成、補正モデル、変更案を返すAPI。
- `band2tab/route.py`：JSON決定木による処理経路の提案。Macの推論にはscikit-learnが不要。
- `models/muscriptor_separation_fusion_review.pt`：検証で選んだ50更新の重み。対応JSONにSHA256と元チェックポイントを記録。
- `models/muscriptor_separation_router_conservative_review.json`：検証で選んだ経路選択モデル。自動適用は無効。
- `reports/presentation_separation/`：全方式の比較CSV、単音／2音／3音以上のCSV、比較図、学習曲線。
- `backups/azure/reports/separation_v1/`：プロトコル、検証選択、全評価、モデル出力、環境、チェックサム。

Macでは、プロジェクトの場所から以下を実行できます。通常の`.venv`が未準備の場合、今回確認した環境は `/private/tmp/chord-v5-qa-env/bin/python` です。

```bash
cd "$HOME/Documents/EEIC_3A/0_後期実験/人工知能演習/music/music_ai_exp"
.venv/bin/python scripts/a_separation_report.py --root backups/azure
.venv/bin/python -m unittest discover -s tests -q
python3 scripts/a_separation_audit.py verify
```

既に回収済みの1区間について、経路の提案を再現できます。

```bash
.venv/bin/python -m band2tab.route \
  --input-dir backups/azure/data/separation_v1/audio/ref_mix_Track00001 \
  --mix-midi backups/azure/reports/separation_v1/midi/ref_mix_Track00001/mix.mid \
  --checkpoint models/muscriptor_separation_router_conservative_review.json \
  --out results/route_review.json
```

候補補正のAPIは `band2tab.fusion.refine(audio_inputs, midi_inputs, checkpoint, mode='review')` です。2つの辞書にはそれぞれ `mix`、`guitar`、`bass` のファイルを渡します。`parts` は元の認識結果、`suggested_parts` と `refinement_changes` は変更案です。未検証の自動適用を防ぐため `mode='apply'` は拒否します。

将来の統合では、分離→原音のMuScriptor→経路提案と進め、提案経路に必要な追加推論だけを実行できます。原音MIDIと分離後MIDIを別保存し、Bは同じ音符形式のまま結果を比較できます。時間表示や進捗、失敗時の原音経路への復帰は統合作業として残っています。Mac上で分離・MuScriptor・GUI全体を通す受入試験も未実施です。

実験の実行順は `a_separation_compare.py prepare / prepare_amp / separate / predict / score`、`a_separation_fusion.py train`、`a_separation_router.py train / train_conservative`、`a_separation_compare.py separate / predict / score --test`、`a_separation_fusion.py evaluate`、`a_separation_router.py evaluate / evaluate_conservative` でした。Azureでは `~/music_ai_exp` で `export PYTHONPATH="$PWD" OMP_NUM_THREADS=4` を設定し、分離・MuScriptorは `.venv-mus/bin/python`、学習・評価は `~/venv/bin/python` を使用しました。既存の固定結果を上書きする再実行は拒否します。

## 次に優先すること

1. 分離の効果が大きい条件を、アプリの比較可能な追加経路としてBへ渡す。自動切替は保留する。
2. 新しい曲群を留保したうえで、既存の実演奏ギター・ベースへ同じ分割のドラム・鍵盤を混ぜた難しい訓練条件を増やす。人工ミックスと自然なバンド録音は区別する。
3. 比較する分離器を増やす場合は、実際にギター／ベースを対象にした重みを選び、同一MuScriptorで最終音符の精度まで評価する。今回のOracleとの差を診断に使う。
4. 開始・終了を直接補正する学習を別条件で試す。音高集合だけの改善でTABの音価が正確になったと扱わない。

今回は新しい演奏や手動音符ラベルを作らず、既存データの未利用音声も活用しました。研究上の価値は、分離・単純結合・学習補正・学習による経路選択を分けて比較し、どこで有効／有害かを再現可能に示した点です。新しい採譜アルゴリズムの最高精度を達成したという主張ではありません。

## 回収と停止の確認

実験関連2,019ファイルのSHA256をMacで照合し、既存分を含む368個のチェックポイントも回収確認しました。368個の独立モデルを学習した意味ではありません。MacのCPUでは候補補正の変更案7件、元MIDI不変、自動適用拒否を確認し、37評価条件の経路提案もAzureの固定結果と一致しました。テスト37件が通過しています。

作業後にAzureを手動停止し、ポータルの**停止済み（割り当て解除）**を確認しました。自動シャットダウンは設定していません。証拠は `reports/azure_separation_deallocated_20261118.jpg` に保存しています。
