# Band2Tab：倍音の誤検出を減らす追加学習

2026年11月20日 / 担当A / 発表用の追加実験と判断記録

## 1. 今回の結論

36回の学習・比較を追加した。深層学習CNNを9回、ロジスティック回帰を18条件、勾配ブースティング木を9条件。CNNは合計10,800更新である。今回も教師あり学習であり、我々が強化学習を行ったわけではない。

目的は、既存モデルMuScriptor mediumの結果に上乗せし、ギターの倍音を別の音符と誤認する問題を減らすこと。独立した別モデルへの全面置換ではなく、元の予測を保ったまま、疑わしい上のオクターブ音符を学習器で確認した。

内部の設定調整用24条件では、小さな改善を示す方式があった。しかし、選択を固定してから再確認した16条件・既知14条件では、新しいギター補正は全方式で0件だった。追加学習によって既存モデルを上回れた、とは結論しない。新方式はアプリに採用せず、原結果と従来の任意補正を維持する。

従来の補正C7は16条件で音符F1を81.842%から82.214%に上げたが、正しい音符を3個失い、余計な音符を18個減らした結果である。「正しい音を一切消さずに改善した」とは説明できない。今回の再点検で、この損失を明示した。

取得済み音源から512個の派生教材を作成した。クリーンな単音と実際の2音の重なりに加え、歪ませた単音と2音も比較した。加工は有効な学習材料になるが、今回の加工条件では、確認用音源への改善の広がりは実証できなかった。

Azureの学習成果はMacへ回収して照合済み。GPU作業終了後に停止済み（割り当て解除）を確認した。Macでの追加比較でもAzureは起動していない。

## 2. 何を学習させたのか

処理の流れ：ファイル読込 → 学習済みAIによるパート分離 → MuScriptor mediumの音符予測 → 今回の確認器 → 原結果と補正案の比較 → Bの編集・譜面表示。

音源分離とMu本体は、今回の実験では固定した。ギターのステム（分離済み音声）から音響特徴を取り、Muが出した音符だけを点検する。ベースの音符をギター用確認器が消すことはない。

例えばC3を弾くと、その2倍の周波数であるC4も倍音として鳴る。周波数の山だけを見ると「C3とC4を同時に弾いた」のか、「C3だけを弾いてC4の倍音が出た」のかが紛らわしい。本物の2音演奏を誤って消さないことが重要になる。

候補は同じギター内で12半音離れ、開始差80ms以内、持続区間が重なる音符対の上側に限定した。曲の端から250msは対象外。判定のために正解音符を入力することはなく、正解は学習時の教師と評価だけに用いた。

CQT（定Q変換）は、波形を時間と音の高さの表へ変える。今回はその表から、下側の基音から第12倍音までを、約0.5秒・24時点で切り出した。24×12の表と4個の補助値をCNNへ入力する。CNNは26,081個の学習可能な数値を持ち、音の強さの並びや変化から「上側の音を残すか」を学ぶ。

比較のため、倍音ごとの平均・変動・前後の変化・相関・強度比を70個の数値に要約し、ロジスティック回帰と木モデルでも学習した。さらに高次倍音と絶対音高を除いた35特徴の方式も試した。特徴抽出にCQTを使うが、今回BTCを新たに学習したわけではない。

推論値は学習器の判断スコアであり、「本当に正しい確率が95%」などの保証ではない。閾値より小さい候補だけを削除し、1区間で消す上限を元のギター音符数の10%とした。元の音符ファイルとアプリの既定動作は保持している。

## 3. 使ったデータと加工方法

学習側172条件、設定調整側24条件を継承した。これは独立した196曲を意味しない。同じ演奏の加工違いを含む。GOATのギター音源、SlakhのミックスとMIDI、GuitarSet、Guitar-TECHS、既存の加工済みベース条件を利用した。

対象となる上側の音符候補は、学習側1,214個、調整側351個。学習側651個・調整側227個は、正しい開始音符または正しい持続フレームを含むため、教師は「残す」とした。開始がずれていても本当に鳴っている音を不用意に消さないためである。音源とラベルの対応が不明な端の音は教師から除いた。

単音として注釈された0.3秒区間を抽出し、有限値・音量・重複を検査して874個の素材を得た。そのうち下側128素材に、実録された12半音上の別素材を対応させた。音程移動による合成ではなく、実際に録音された異なる音高を重ねた。

| 1組から作る教材 | 上側音の正解 | 狙い |
| --- | --- | --- |
| クリーンな単音 | なし | 倍音を別音として数えない |
| クリーンな2音 | あり | 本物のオクターブ演奏を残す |
| 歪ませた単音 | なし | 歪みで増えた倍音に対応する |
| 歪ませた2音 | あり | 歪んだ実音も消さない |

128組×4条件＝512例。各組の音高・長さ・時刻・最終RMS音量を揃え、音量だけで答えが分からないようにした。上側音量は-9/-3/+3dBから抽選。非対称tanh歪みは3段階の強さと3段階のバイアスを使い、直流成分を除いて音量を再調整した。

加工教材は学習側の元演奏だけから作り、設定調整側の演奏を混ぜていない。加工は独立した演奏者や新しい楽曲を増やすものではない。素材は発音25ms後から切って人工的なフェードを付けたため、本物のピッキングの立ち上がりを十分には表現していない。合成教材そのものへMuを実行した性能試験でもない。

## 7. 失敗を次の学習につなげる

16条件では127個の対象対のうち、上側の開始が正しい79個、開始は外れたが正しい持続を含む2個、正しい持続もない46個だった。14条件も対象127個で、順に73個・17個・37個。つまり、安全に消すべき誤検出は残っている。対象がゼロだったため改善しない、という説明にはならない。

内部で選んだ70特徴回帰のスコアは、16条件の最小値0.280、14条件0.211。削除閾値0.05を下回る候補は合計0個だった。内部24条件で通った少数の事例と、確認用音源との間でスコア分布が違う。第6倍音限定や木モデルでも、この問題を解消できなかった。

今回分かったことは「歪ませれば必ず精度が上がる」ではなく、「単音の倍音と本物の2音を対にする教材は構成できるが、実際の分離音・アタック・余韻への接続が難しい」という点である。短い倍音表だけでは奏法や重なりの文脈が不足する可能性がある。これは原因候補であり、まだ実証した原因ではない。

次の最優先は、追加の加工前に元音とラベルの対応を点検し、48+54個の開始誤検出候補を、倍音・分離漏れ・開始ずれ・残響などへ分類すること。利用済み確認用音源は診断に限定し、同じ元演奏を調整側と学習側の両方に使わない。

その後、訓練側の実際の発音開始を残し、上側音の遅延・音量・長さを変えた対を作る。単音を歪ませるだけでなく、本物の2音と、分離処理を通した音も教師付きで対応させる。単音／2音でタイミングや音量だけから答えが分からない対照を作り、同じ元演奏の加工違いは同じ分割へ置く。

再学習は「前後の音符・オンセット証拠を追加すると持続を壊さず誤検出を減らせるか」という1つの仮説で行う。今回の結果を見て削除閾値だけを上げない。未開封の11元曲はモデル・設定を固定した後に一度だけ評価し、悪ければそのまま発表する。11元曲だけで全ジャンルへの優越は証明できない。
