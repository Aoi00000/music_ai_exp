# 担当A 初回実験結果（2026-11-17）

**比較実験は完了。独自モデルはまだ実用精度に達していません。** 既存モデルより高精度になったという結論は出せません。Macアプリの主採譜を今回の独自重みに置き換えないでください。

## 何を学習したか

CQT→CNN→双方向GRU→音高別の開始/持続/終了確率を出すNoteCRNNを新規学習しました。A0は単独パート、A1はA0に他楽器を重ねたデータも追加。両者ともseed17、batch4、4秒窓、500更新（100更新×5区切り）です。公開モデルの重みを追加学習したものではありません。

## 同じ留保データによる結果

各条件の曲別Note F1を平均しています。音高（オクターブ込み）と発音開始±50msを照合し、値は0〜1。単独音と人工的な混合音の両方を含みます。閾値は検証用112パートで確定し、モデル・分割・閾値の指紋を凍結してから留保テスト90パートを評価しました。

## 発表で説明できること

- 学習・検証の誤差は下がりました。ただし、誤差が下がることと音符が正しく取れることは別です。
- A1は混合ギターでNote F1が約0.0054上がりましたが、元曲群単位の差の区間は0をまたぎます。ベースでは低下し、全体として改善したとは言えません。
- 余計な音の検出が多く、単独ギターでA0の適合率は約0.067、再現率は約0.418でした。モデルが音を出すことと、正しい音を選べることを区別する必要があります。
- 音符検出の比較に加え、時刻ごとの全音高集合、単音/2音/3音以上の正解別Frame F1を測定できる環境ができました。

プロジェクトの製品上の狙いは、コード名とは独立したギター/ベースの実音一覧を見ながら、誤りを修正してTAB下書きを得ることです。今回測定できたのは音符検出までであり、編集が速くなることやTABの弾きやすさは未検証です。研究としての価値を主張する際には、機能の統合による価値と学習による精度改善を分けてください。

## 次に調べる順序

1. 検証データで誤検出を確認し、特にオンセットのクラス不均衡、継続学習による変化、音域ごとの誤りを調べる。損失や更新数の効果は別条件として比較する。
2. ベース用の独立曲が少ないため、Slakh reduxから元MIDIの重複を除いて曲数を増やす。訓練データ増加の効果を検証する。合成音源の結果を実録音の精度と同一視しない。
3. 追加実験では今回のテストを調整に使わず、重複を除いた新しい留保群を固定する。実際の分離出力と自然な録音にも別評価を設ける。
4. 主採譜は既存モデルを基準とし、独自モデルによる確認支援は誤り検出の適合率・再現率を別途測る。BとMac上で統合し、修正にかかる時間とTAB出力の不具合を測る。
