# 音符候補の選別と、次の基盤モデル適応の開発記録

この後、LoRA追加学習による改善を確認した。[新しい途中結果](YOURMT3_PROGRESS_20261118.md)を参照。以下は候補選別段階を終えた時点の記録。

2026-11-18時点の**開発・検証結果**。最終評価の成績ではなく、実用精度の達成も意味しない。

## 実施済み

- MuScriptorの原音・推定ギター・推定ベースの全打楽器以外の音符を候補にする。対象外の楽器ラベルも捨てず、ギター／ベースを独立に判定する。
- CQTの直接特徴と固定したA8音響特徴に、MLPまたは2層Transformerを組み合わせ、音符の採否・楽器・開始／終了の補正を教師あり学習した。強化学習ではない。
- 元曲追加、実演奏ギターの追加、難しい混合、重複候補の教師信号、誤追加の重みを変え、9条件を各3,000更新まで学習・検証した。最良更新は検証だけで選び、3,000更新の最後の重みを自動採用していない。
- 新しいSlakh元曲52曲をファイル単位で取得。以前使用した元MIDI UUIDを除き、ミラーの固定revision・ハッシュ・復号を検査した。
- 訓練音源の点検で、MIDI音符に対して波形がほぼ一定のDC成分しかない例を発見。予測を見ずに決めたAC成分の品質基準を、追加した全分割へ学習前に適用した。訓練2曲・評価1曲を除外し、実使用は訓練30／検証8／評価11曲。元音声・元MIDIは書き換えていない。
- 取得済みのクリーンなGuitar-TECHS訓練32区間も、別条件として再利用した。新しい奏者32人という意味ではない。

## 検証で分かったこと

曲ごとの指標を平均し、さらにデータセットを均等平均した値。

|方式|Note F1|楽器込みFrame F1|音高集合F1|完全一致|終了を含むF1|
|---|---:|---:|---:|---:|---:|
|原音MuScriptor|0.4874|0.5099|0.5742|0.1735|0.2836|
|6s分離＋MuScriptor|0.6164|0.6295|0.6513|0.2805|0.3642|
|検証で選んだMu候補補正|0.6584|0.6790|0.6928|0.2999|0.3826|
|新しく導入したYourMT3+|0.7900|0.7414|0.7542|0.4193|0.6654|

Mu候補補正では、最初の通常116区間のMLP・500更新が総合基準で最良だった。曲数やモデルを増やしても、全体では一貫して改善しなかった。複数候補が同じ正解音を重複して出さないよう、全候補を正例にする方式と、正解1音に代表候補1個を対応させる方式も比較した。後者でNote F1が上がる条件はあったが、Frame等とのトレードオフが残った。

候補の取り出しにも限界がある。検証の新Slakhでは、楽器を完全に正しく振り分けられると仮定しても、候補にある正解音は開始許容50msで約83.5%、120msで約85.7%（音符数をまとめた再現率）。これは達成可能な精度の保証ではなく、時刻修正にも制約がある。候補にない音を、選別器だけでは作れない。

そこで、作者の公開配布からYourMT3+の `YPTF.MoE+Multi (noPS)` を追加した。固定revision `5e66c1ea173a8186e0d20432b841d3180cc015b5`、チェックポイント約562MBと必要な推論用コードだけを取得し、配布ハッシュを確認した。元のCUDA／Mu環境は変更せず、追加ライブラリは別の場所に置いた。チェックポイントの未使用訓練メタデータを実行せず、重みを安全に読み、モデルへの重みの不足・余剰がないことも確認した。

YourMT3+はSlakhやGuitarSetを事前学習に含む。今回の自分たちの分割と、公開重みの事前学習との非重複は保証しない。合成バンドだけの高得点を自然なバンドの精度として扱わない。

実際、YourMT3+の検証Note F1は新Slakhで0.943だった一方、FiloBass単独では0.226だった。既知パートを教える診断でも音高・開始の誤りが残り、楽器名の置換だけでは直らない。基盤モデルをそのまま置き換えれば全条件が良くなるわけではない。

## 次の開発段階

同じ分類器を長く学習するより、良い既存モデルの音響・音符予測そのものを、実演奏の不足領域に適応させる段階へ進める。YourMT3+の元の重みを固定し、小さな追加行列だけを学習するLoRAを検討・実装する。実演奏のベース／ギターを教師とし、合成音源の良い結果を壊さないための保持条件も比較する。

この段階はまだ実測済みの改善ではない。新11曲の最終評価は、基盤モデル側の開発・検証選択が終わるまで全体のロックを保持する。Mu候補補正の一群だけ先に選択を固定し、他の方式の開発中に最終評価で調整しない。

動作テストと認識精度、合成と実演奏、検証と最終評価、音符認識とTABの完成度を分けて記録する。自動適用は現在も無効。成果は途中でもMacへ回収し、Azureを使い終えた時点で手動の割り当て解除を確認する。
