# 持続時間を重視した補正学習・追加データ・評価（2026-11-18）

主採譜器はMuScriptor mediumのまま固定しています。今回は追加する補正器の学習方法を変え、実録音を増やしました。**人工ミックスで楽器の割当が改善しましたが、すべての音源・指標の向上は達成していません。** 新しい補正器もreviewモードで保存し、自動適用は無効です。

## 結果を最初に確認する

数値は0〜1のF1です。Note F1は音高と開始時刻±50ms、Frame F1は20msごとの持続音を照合します。以下のFrame F1は**楽器と音高の組**で採点しており、余計な別楽器も誤りとして数えます。

|評価対象|録音・区間数|MuScriptor単体 Frame F1|追加データで学習した補正候補|
|---|---:|---:|---:|
|新しいベース奏者＋ギターの人工ミックス|7|0.4310|0.4922|
|同じ未学習ベース奏者の単独音|7|0.8860|0.8860|
|未学習のギター奏者P3|10|0.5838|0.5786|
|既に観察済みのIDMT（回帰確認）|22|0.7679|0.7771|

人工ミックスのNote F1も0.4985→0.5432、楽器込みの音集合完全一致率は0.0403→0.1166でした。一方、**ギターとベースを合計して音高だけを見るFrame F1は0.6587→0.6565で、改善していません。** 今回の主な効果は楽器の割当であり、鳴っている全音の認識が一律に改善したとは言えません。

人工ミックスの改善は主にTyrone Wheelerの6区間（楽器込みFrame F1 0.4365→0.5078）で、Wayne Dockeryの1区間は0.3982のままです。奏者・曲による差が大きいことも示しています。

P3のNote F1は0.6047→0.6031。従来の合成ミックス3区間の音高集合Frame F1も0.3848→0.3834と小さく低下しました。IDMTのNote F1は0.8331→0.8591ですが、これは既に観察済みの比較セットであり、新規の外部テストとは区別します。

新評価の奏者はP3のギタリスト1名、FiloBassのベーシスト2名です。FiloBassの単独音と人工ミックスは同じ7曲の組なので、独立した14曲ではありません。公開MuScriptorの事前学習との非重複は保証できません。自然なバンド演奏の新評価もまだありません。

## 学習した内容を理解する

前回は、MuScriptorの音符を正解の開始時刻±50msだけで対応付け、「ギター／ベース／対応なし」を学習しました。しかし、少し遅れて始まった音でも、音高や持続部分は正しい場合があります。それを丸ごと消すと、発音開始の指標だけ良くなって持続音の認識が悪化することがあります。

今回は正解を、**鳴っている時間の重なり80%＋開始時刻の対応20%**で作ります。例えば推定が0.1〜1.1秒、正解が0.2〜1.2秒なら、開始は100msずれていても0.9秒は正しく重なっています。その音を一律に「不要」と扱わないよう学習します。

- MuScriptor本体は追加学習していません。
- 学習したものは5,507パラメータのEventRefiner（CQT由来の82特徴→64ユニット→3クラス）です。元のMuScriptorの楽器指定も初期の優先値にします。
- 長い音の誤削除を重視するため、候補の音長を上限3秒で重みに使い、録音ごと、さらに単独音／ミックスの領域ごとの総重みを調整します。
- AdamW、学習率0.001、重み減衰0.001、seed17、150回の全件バッチ更新です。追加条件はデータが多い分、提示した候補数と計算量も増えています。固定計算量での厳密な比較ではありません。
- 音源を切り出す前から続く音も持続の正解に含めます。その切出し端を本来の発音開始とは扱いません。
- これは既存の候補を残す・対象外と提案する・楽器を再判定するモデルです。**新しい音高の生成や、開始・終了時刻の修正はしていません。** Offset F1が変わるのも採用する音符・楽器の変化によるものです。

## 追加したデータと分割

|データ|今回の使い方|
|---|---|
|GuitarSet|訓練を12録音から80録音へ拡張。元曲群単位の分割を継承。検証用4録音と、人工ミックスの相手も同じ分割内から選択。|
|BabySlakh|訓練14曲、検証3曲をそれぞれ3位置で切り出し。別区間でも同じ元曲なので、独立曲数が増えたとは数えない。|
|Guitar-TECHS P1|既に同期検査を通った32録音を利用。|
|Guitar-TECHS P2|DI音声＋MIDIを新規取得。40録音のうち固定の同期・音域・時刻検査を通った32録音を訓練に追加。|
|Guitar-TECHS P3|未使用だった音楽12録音を事前に品質検査。10録音の全体を新評価に使用し、2録音は同期不確実として除外。|
|FiloBass|公式48曲の分離済み実演奏ベースと音声同期MIDIを取得。演奏者を8名・34曲の訓練、2名・7曲の検証、2名・7曲の評価に分離。|

FiloBassは各曲から固定12秒を取り出し、単独ベースと、同じ分割のGuitarSetを重ねた人工ミックスを作りました。ベース対ギターのRMS比は-6／0／+6dBを曲IDのハッシュで決めています。別々の曲を重ねた制御実験であり、自然なバンド録音ではありません。評価区間の最初・最後0.25秒は切出し境界の影響を避ける固定の除外窓です。

FiloBassのMIDIは必ず `midi_fully_aligned` を使います。楽譜由来のMIDIやCSVの音高を、そのまま音声の正解にはしません。公式の同期MIDIにはGM program 26が入っていますが、データセットの内容はベースです。楽器ラベルは既知のベースステムであることから与え、音高は移調しません。訓練側3曲・計283音の長い音の内部でYINを照合し、1半音以内の割合は約81〜99%、中央値の誤差は-0.17〜+0.04半音でした。これはオクターブの診断であり、全注釈の完全な人手検証ではありません。

P2は必要なZIPメンバーのCRC32とSHA256を記録しています。ZIP全体のMD5を検証した意味ではありません。FiloBassの434.1MB ZIPとP3のZIPは配布元のMD5を照合しました。取得した音声、元MIDI、メタデータもMacへ回収済みです。

P3には配布元が注意する音声とMIDIの位置ずれがあるため、モデル出力を見る前に固定のアタック同期検査を行いました。元注釈のままの採点も保存しています。補正の有利・不利の方向は元注釈でも同じで、P3での一律な改善は確認していません。

両条件の検証音源は同じ27区間です。ミックス／単独音を同じ重みで平均しています。検証での採用条件は、音符とFrameの平均F1を最大化しつつ、各領域・各楽器でMuScriptor単体からNote/Frameを悪化させないことです。何もしない条件も含めました。

拡張条件を検証だけで採用し、その後に新評価を実行しました。選択された更新回数は150、閾値0.75、元判定との差0.2です。小規模条件は25更新が選ばれました。scoreはモデルの出力値で、校正された正答確率ではありません。**評価用P3・FiloBassで閾値を調整し直したり、モデルを選び直したりしていません。** seedは1種類で、独立した奏者も少なく、統計的優位性やSOTAの主張はしません。

## Macと担当Bへの引き継ぎ

新しい重みは `models/muscriptor_refiner_duration.pt`、出所とSHA256は `models/muscriptor_refiner_duration.json` です。旧版は上書きせず残しています。データ形式とAPIは前回と同じなので、Bは重みのパスを変更して補正候補を受け取れます。画面やTAB処理は今回変更していません。

Macのターミナルで、以下の場所から実行します。

```bash
cd "$HOME/Documents/EEIC_3A/0_後期実験/人工知能演習/music/music_ai_exp"
.venv/bin/python -m band2tab.refine \
  --audio inputs/song.wav --midi results/song.mid \
  --checkpoint models/muscriptor_refiner_duration.pt \
  --mode review --out results/song_refinement.json
```

`parts` は元のMuScriptorのまま、`suggested_parts` と `refinement_changes` に学習補正の候補を返します。生MIDIを上書きしません。自動適用は無効で、`--mode apply` はエラーになります。今回のMac確認環境は `/private/tmp/chord-v5-qa-env/bin/python` ですが、Bの統合後は通常の`.venv`を使います。

## 次に優先すること
